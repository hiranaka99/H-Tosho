The Tasks tab, as it ships and as it could.

An Impeccable critique of web/src/pages/Jobs.tsx found five priority issues. Each section below puts a recreation of the live tab beside a working version of the fix, using the app's own tokens and the same ten sample tasks. Both sides are interactive. Nothing here touches the real code.

1Stopping a task should take two deliberate steps P1 · harden

Live: Cancel is the heaviest control in the row, fires on one click, and in the details panel it's the first focusable element, so Enter right after opening Details kills the job. The app's own copy says cancelled work is not undone.

Proposed: a quiet “Stop” that opens an inline confirm which says what is kept. Focus lands on “Keep running”. It reverts on its own after 6 seconds.

Live
Proposed

What changed

  • Outline “Cancel” becomes ghost “Stop”, danger tint on hover only.
  • Inline confirm states what is kept: “The 42 of 118 series already processed keep their new metadata.”
  • Default focus on “Keep running”; Esc or 6 s timeout reverts.
  • Label is “Stop task”, so it never collides with a dialog's own Cancel.

Code it touches

  • actions() at Jobs.tsx:407-415, shared by list and panel.
  • Dialog onOpenAutoFocus at :477 to focus the title, never an action.
  • One small ConfirmInline component, no new dependency.

2Lead with the verb; give covers back their space P1 · layout

Live: each row is ~153px tall on desktop: a 96×128 cover tile (empty on five of these ten rows) beside three lines of text. The noun is the bold title, so two rows read “Manga” and the verb is 12px muted. Four identical green “Completed” pills repeat.

Proposed: About half the height. Verb first, target second. Glyph chip when there's no series. Completed is a quiet check, and pills are kept for exceptions.

What changed

  • Cover only when a series exists, at 40×54. Otherwise a type glyph (scan, match, merge, watch, edit, delete).

  • Result line carries the number that matters: 19 matched · 4 failed, with the failed count linked.
  • Right column: status, then relative time, then one action. “Details” goes away: the title is the button.
  • Selection gets a primary outline and tint. The failed tint survives selection.

  • jobTarget() stays; add jobGlyph(type) and split target from verb.
  • JobStatus at :228 returns a check for clean completions.

3When a task fails, say what happened and what to do first P1 · clarify

Live: the panel opens on a generic “Stopped with an error”, then Retry and Clear side by side, then a raw stack trace, and only then the sentence that explains it. The app knows to wait 60 seconds and makes you count. On a permissions error there's no guidance at all, and Retry is offered anyway.

Proposed: a “what happened” card first, with the one action that fits. The raw error moves into a disclosure.

Proposed panel

What changed

  • Plain-language headline, then one sentence of consequence. “Nothing was changed” only where the job verifies it.
  • One primary action per cause: Retry in 0:42 counts down; permissions offers Open Settings → Libraries and demotes Retry.
  • Raw message and trace become “Error details” with Copy.
  • Logs open by default for failures, one line per entry, error lines tinted.
  • “Clear task” becomes a ghost “Remove from history” in the footer, away from Retry.

Code it touches

  • Panel body at Jobs.tsx:487-508, RecoveryActions at :238, jobOutcome() generic fallback at :146.
  • Needs server-side recovery mapping for more error classes (job.recovery already exists for rate limits). The EACCES copy here is proposed, not shipped.
  • jobSummary() fallback “Open details for the error.” at :187 when no message is recorded.

4Counts you can see, one vocabulary, a phone that shows tasks first P2 · clarify + adapt

Live: status counts hide inside a select, the page says both “tasks” and “activity”, the sidebar says “Failed tasks · 2” while the filter says “Needs attention (3)”, and the default is All. On a phone the first task starts about 430px down.

Proposed: tabs with counts (the app's own SegmentedTabs pattern), landing on Needs attention when anything needs attention. Search and a filter button share one row. Clear moves into the view it applies to.

What changed

  • Select → tabs: All 10 · Active 2 · Needs attention 3 · Finished 5. Finished now excludes items already counted as needing attention, so the numbers add up (live: 10 / 2 / 3 / 6).
  • Default tab is Needs attention if above zero, else Active, else All.
  • “Clear failed tasks” moves into the Needs attention view as “Clear 2 failed”.
  • Per-tab empty copy that says what the state means.
  • Sidebar label “Failed tasks” → “Needs attention” to match.

Code it touches

  • SegmentedTabs already exists in ui.tsx:305.
  • Empty states at :452; sidebar copy in SidebarStatus.tsx.

5Watch a running task without losing the list P2 · adapt

Live: Details opens a modal drawer that dims and locks the list. A running task's logs are collapsed (they're only open for failures), there's no ETA, and each row has three tab stops with no keyboard way to step through tasks.

Proposed: from 1280px, a non-modal inspector beside the list. It's live: progress, ETA, a freshness stamp and tailing logs. ↑ ↓ move selection, Esc clears it.

Proposed ↑↓ move · Esc clear

What changed

  • ≥1280px: 440px sticky inspector, list stays interactive, no scrim. 1024-1279px keeps today's overlay without the scrim. Phones get a bottom sheet.
  • Running view: 42 of 118 · 36% · ~12 min left, “Updated 2s ago”, logs open and following. Stop is a quiet link that uses fix 1.
  • Roving tabindex: one tab stop for the list instead of 14. ↑ ↓ select, Enter opens, Esc clears.
  • Rows don't re-sort under the pointer while it's over the list.

Code it touches

  • Dialog at Jobs.tsx:476-511: becomes a layout column at lg, the existing dialog stays below it.
  • Log default at :507: open when active or failed.
  • Poll sort at :421-424: freeze order while hovered.
